How to check a JSON file for mistakes with Python

Short answer

JSON is a plain text format many apps use for settings and data. One missing comma and the app refuses the whole file, often with a message that does not say where. This lesson builds a small read-only Python tool that reports the line and column of the mistake. It also reports three things Python itself lets through or rejects without much help: a name repeated inside one object, a byte order mark at the start, and NaN or Infinity.

Follow along and build it step by step. You add each file yourself, run each command, and see the real recorded result.

Common mistakes

  1. Fixing the line the error points at. Python reports where it got stuck, which is often the line after the real mistake. A missing comma is reported at the start of the next item, as the practice file shows.
  2. Trusting "no error" from a program. The Python documentation says its JSON reader accepts a repeated name and keeps only the last value. A file can load without complaint and still have lost data.
  3. Ignoring an invisible first character. A file can start with a byte order mark, an invisible marker that some editors add. The Python documentation says its JSON reader raises an error when one is present, and the file can look fine in an editor.
  4. Treating a pass as proof the data is right. These checks look at the format, not the meaning. A file can pass and still hold a wrong value, or be refused by a stricter program.

Frequently asked questions

How do I check a JSON file for mistakes with Python?

Read the file and give its text to the json module. If it is not valid, the error carries a line and a column. This lesson builds a small tool that reports those and adds three extra checks.

Will this change my file?

No. The tool only reads the file. A test checks that one small test file has the same bytes and modified time after a run. That is the only evidence for this claim.

Why does the tool flag a repeated name?

The Python documentation notes that the JSON standard says names in an object should be unique but does not say how to handle repeats. Python keeps only the last value. A repeated name is usually a copy and paste slip.

Why flag NaN and Infinity?

The Python documentation says the JSON standard does not allow them but Python accepts them by default. Other programs may refuse a file that uses them.

Does it list every mistake in the file?

No. Python stops at the first syntax error, so the tool reports that one. Fix it and run the tool again to find the next. Repeated names and a byte order mark are reported in the same run.
